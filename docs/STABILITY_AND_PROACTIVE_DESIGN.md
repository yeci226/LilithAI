# LilithAI stability and proactive dialogue design

## Runtime flow

1. The player, a built-in game line, idle time, a return from absence, or a Lilith state change provides context.
2. Conversation history records the source separately as `player`, `ai`, `game`, or `legacy`.
3. Player requests run immediately. Proactive cues pass model/API readiness, cooldown, probability, focus, dialogue-idle, and UI-idle gates.
4. The provider returns a compact reply contract. Supported providers use JSON mode; malformed or transient responses receive one bounded retry.
5. The game dialogue manager receives the reply. Rejected dialogue is retried a bounded number of times and then discarded so chat never remains locked.
6. A reply is committed to memory only after the game accepts it.

## Conversation sources

| Source | API role | Meaning |
| --- | --- | --- |
| `player` | `user` | Explicit player input |
| `ai` | `assistant` | A reply generated by LilithAI |
| `game` | `assistant` | Built-in Lilith dialogue captured as shared context |
| `legacy` | Existing role | A history entry written before source tracking existed |

Built-in game lines are labelled as game context before being sent to a model. AI-generated dialogue is suppressed from the game-dialogue listener while it is submitted, preventing it from being recorded twice or misclassified.

## Proactive dialogue

Supported cues:

- quiet idle time;
- returning after a configurable absence;
- built-in game dialogue;
- clothing, sleep, lying, or sitting state changes.

All cues share one global cooldown. Event cues also use a configurable probability. Proactive output cannot change clothing or execute commands, and it is skipped while native dialogue, an AI request, speech generation, the player choice menu, or the chat window is active.

Settings:

- `Companion.ProactiveDialogue`
- `Companion.ProactiveCooldownMinutes`
- `Companion.ProactiveChancePercent`
- `Companion.ProactiveReturnMinutes`

The first three are available directly in the Lilith settings tab.

## UI integration

- AI and voice settings live together in the Lilith tab.
- Provider, model, voice, chance, and cooldown rows have explicit previous and next controls.
- The settings content uses Unity's native `ScrollRect`; periodic discovery does not reset the scroll origin.
- Opening settings preserves the player's selected tab.
- Cloned native labels have their inherited localization behaviours disabled before custom text is assigned.
- The chat window maps the verified native NamingView confirm/refuse buttons by hierarchy and lays them out with their native sizes.

## Failure containment

- Optional Unity lifecycle stages retry after one skipped invocation instead of remaining disabled until restart.
- Provider `Retry-After` values are honoured up to 30 seconds.
- Retry requests use a lower temperature.
- OpenAI-compatible array content is accepted in addition to string content.
- Dialogue display attempts are bounded and always unlock the next chat turn.
- The shared native dialogue bubble is no longer overwritten while the game dialogue manager is busy.

## Verification

`tests/LilithAISmoke.csproj` covers configuration migration, memory recovery, source compatibility, proactive policy, reply parsing, provider retry behaviour, JSON mode, response content shapes, speech fallback, and TTS policy. GitHub Actions runs it on every push and pull request. `scripts/Test-PluginInterop.ps1` separately compiles `Plugin.cs` against the local BepInEx and Unity interop assemblies.

Unity hierarchy, scaling, pointer input, and native dialogue interaction still require an in-game smoke pass because the game assemblies and live scene are not available to the protocol test project.
